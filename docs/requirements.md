# 要件定義書（v0.1 ドラフト）
## 「月夜が魅せる物語」マルチエンディング・ストーリーゲーム

---

## 0. 本ドキュメントの位置づけ

本書は、クトゥルフ神話TRPGシナリオ『月夜が魅せる物語』（作:唯燐、文:じゃこ缶・きりぅ）を原作とする、
マルチエンディング方式のデジタルストーリーゲームの要件をまとめたドラフトである。
既存の「AIがキーパー(KP)を務めるTRPG風ゲーム」とは別プロジェクトであり、
TRPG的な自由裁量プレイではなく、あらかじめ設計された選択肢と分岐によって物語を進める形式を採用する。

内容は今後の相談を通じて更新される前提の**v0.1ドラフト**であり、確定仕様ではない。

---

## 1. 背景・目的

- KP代行という形で『月夜が魅せる物語』を運営してきた経験を活かし、同シナリオを題材にした
  一人プレイ可能なデジタルゲームを制作する。
- TRPGは「毎回KPを立てて遊ぶ」コストが発生するのに対し、本プロジェクトはそのコストなしで
  何度でも・一人でも遊べる形にすることを狙う。
- 既存のAI-KP作品が「TRPGのライブ感の再現」を志向するのに対し、本作は
  **あらかじめ作り込まれたマルチエンディング構造**によって、原作の魅力（コズミックホラー、
  陰謀劇、キャラクタードラマ）を別の角度から再体験できるものを目指す。

## 4. ゲームコンセプト

- **ジャンル**：ビジュアルノベル／アドベンチャー ＋ 育成・シミュレーション要素
- **トーン**：現代日本（2016年12月・東京）を舞台にしたコズミックホラー。都市の日常に紛れ込む
  邪神信仰と陰謀、失踪事件の謎解き
- **コアループ（提案）**：
  1. 日ごとに行動（聞き込み・調査・休息・NPCとの接触）を選択する
  2. 選択・調査の成否によって「調査力」「正気度(SAN)」「NPCとの関係値」が変動する
  3. 各種パラメータとイベントフラグの組み合わせにより、後半の分岐・エンディングが変化する
- **想定プレイ時間**：1周 2〜4時間程度（MVP段階ではさらに短い一区切りを想定）、
  複数エンディング回収を前提に周回性をもたせる

## 5. ストーリー設計

### 5.1 原作の全体プロット（要約）

1. **導入**：2016年12月21日夜、新橋の居酒屋「夜叉」に集まった探索者たちが、私立探偵・瑞名慧から
   「東風谷雪」という少女の捜索を依頼される。
2. **背景**：東風谷雪は2015年に起きた「東京23区連続行方不明事件」（28人が失踪）の被害者の一人で、
   邪教「星の知恵派」に拘束され、シュブ＝ニグラスの眷属「ゴフン・フーパジ・シュブ＝ニグラス」へと
   変貌させられていた。親友の間宮凛久も同様に囚われ、洗脳されている。
3. **調査**：探索者は「満月と新月の教団」「星の知恵派」「銀の黄昏教団」「バベッジ・インコーポレイテッド」
   といった複数組織の陰謀に巻き込まれながら、東風谷雪・間宮凛久の行方と、真の黒幕「遠藤啓介」
   （実は"隠された女神個体"）の企みに迫っていく。
4. **クライマックス**：12月29日21時、哲学堂公園でシュブ＝ニグラス降臨の儀式が行われる。
   探索者の調査・行動の成果次第で、この儀式の結末が大きく変わる。

### 5.2 分岐フラグ（原作の結末条件をゲーム用に整理）

原作「14.結末」に基づき、以下の主要フラグでエンディングが分岐する構造を踏襲する。

| # | フラグ | 内容 |
|---|---|---|
| F1 | ムーンレンズ奪取 | 儀式のキーアイテムを哲学堂公園で奪取できたか |
| F2 | 東風谷雪 救出 | 生還させられたか |
| F3 | 間宮凛久 救出 | 12/28 21:00までに洗脳を解除できたか（タイムリミットあり） |
| F4 | 死へと誘う印 解除 | ナイ牧師の切り札を無効化できたか |
| F5 | 遠藤啓介の野望阻止 | 対話・説得・実力行使等で真の黒幕を止められたか |

- 理論上の組み合わせは最大32通りだが、ゲームとしては**代表的な5〜7エンディング**
  （例：トゥルーエンド／グッドエンド／複数のノーマルエンド／バッドエンド／
  真の黒幕ルートの特殊エンド）に集約し、フラグの達成度に応じて**エピローグの記述が
  差分で変化する**形にする（フルボイスの個別分岐ではなく、共通ルート＋差分テキストで
  組み合わせ数を吸収する設計を提案）。
- 具体的な集約案・各エンディングの分類は、次の相談ステップで確定する。

## 6. ゲームシステム要件（提案）

### 6.1 ビジュアルノベル要素
- 地の文＋会話テキスト表示、選択肢分岐、背景・立ち絵・BGM/SEによる演出
- 既読スキップ、バックログ、オートセーブ／複数セーブスロット

### 6.2 育成・シミュレーション要素（本作の独自性のコア）
- **日付・時間帯システム**：原作の12/21〜12/29という限られた期間を、
  「日×時間帯（例：昼／夕方／夜）」の行動枠として扱う、カレンダー型の進行にする
- **調査力パラメータ**：原作の「技能ロール」「情報取得難度ランク0〜4」の概念を
  ゲーム用のステータス（知識・観察・交渉・オカルト等）に翻案し、育成対象とする。
  数値が高いほど有利な選択肢・入手できる情報が増える
- **正気度(SAN)**：ホラー演出・戦闘・真実の開示のたびに消費されるリソース。
  低下すると使える選択肢が狭まる／専用の悪い分岐に近づく
- **NPC関係値**：瑞名慧・久美啓太・東風谷雪・間宮凛久など主要NPCとの関係値を管理し、
  終盤の協力可否や個別エピローグに反映する

### 6.3 探索パート
- マップ選択式（原作に登場する居酒屋「夜叉」「中野ヒカリエビル」「哲学堂公園」等の
  地点をリスト／簡易マップから選び、調査コマンドを実行する形式を提案）
- コマンド選択の結果は「調査力」パラメータや既存フラグに応じて分岐する

## 10. プラットフォーム・技術要件（提案）

非公開・身内配布・プロトタイプ実装まで進める前提での提案：

| 項目 | 提案内容 | 理由 |
|---|---|---|
| プラットフォーム | ブラウザで動くWebアプリ | インストール不要で身内に共有しやすく、この開発環境（Claude Code）で構築・プレビュー・反復がしやすい |
| 技術スタック | React + TypeScript（Vite） | UIコンポーネント化しやすく、育成/シミュレーション要素のような状態管理と相性が良い |
| セーブデータ | ブラウザの localStorage | サーバー不要でシンプル。将来的にエクスポート/インポート機能を追加可能 |
| 配布方法 | 静的サイトとしてビルドし、身内にURLまたはビルド一式を共有 | 非公開範囲を保ちやすい |
| 代替案 | Ren'Py（Python製ノベルゲームエンジン） | ノベルゲーム然としたUI・セーブ／ギャラリー機能を標準装備。ただし本環境での反復開発・ブラウザ確認との相性は劣る |

→ 上記はあくまで提案。Ren'Py案を含め、次の相談で確定する。

## 11. 非機能要件

- 対応言語：日本語のみ
- 対応環境：デスクトップブラウザ（Chrome等）を優先。スマホ対応は将来検討
- パフォーマンス：静的アセット中心のため高負荷処理は想定しない
- アクセシビリティ：テキストサイズ調整、既読スキップなど基本的な配慮を検討

## 12. スコープ定義（MVP／段階リリース案）

原作は100ページを超えるボリュームがあるため、一括実装は工数リスクが高い。以下の段階分けを提案する。

- **フェーズ0（本ドキュメント）**：要件定義
- **フェーズ1（MVP）**：導入部（12/21 居酒屋「夜叉」〜東風谷雪との遭遇イベントまで）＋
  ゲームシステムの土台（カレンダー進行、SAN、調査力、セーブ）を実装し、1つの簡易エンディングまで通しで遊べる状態にする
- **フェーズ2**：中盤の調査パート（各組織のルート）を実装し、分岐フラグを本格稼働させる
- **フェーズ3**：クライマックス〜全エンディングの実装、演出・アセットのブラッシュアップ

## 13. リスク・注意事項

- **ボリュームリスク**：原作のシナリオ量が多く、全要素の忠実な再現は工数が大きい。
  MVPで「面白さ」を検証してから範囲を広げる
- **権利リスク**：非公開前提のため現時点では低リスクだが、将来の公開判断時は原作者への確認が必須
- **ホラー表現**：カルト・洗脳・身体変容など原作の重い題材をどこまでゲーム内で描写するかは
  表現方針として要相談（身内向けなので原作準拠でよいか、マイルドにするか）
