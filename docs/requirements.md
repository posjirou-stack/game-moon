# 要件定義書（v0.1 ドラフト）
## 「月夜が魅せる物語」マルチエンディング・ストーリーゲーム

---

## 0. 本ドキュメントの位置づけ

本書は、クトゥルフ神話TRPGシナリオ『月夜が魅せる物語』（作:唯燐、文:じゃこ缶・きりぅ）を原作とする、
マルチエンディング方式のデジタルストーリーゲームの要件をまとめたドラフトである。
既存の「AIがキーパー(KP)を務めるTRPG風ゲーム」とは別プロジェクトであり、
TRPG的な自由裁量プレイではなく、あらかじめ設計された選択肢と分岐によって物語を進める形式を採用する。

内容は今後の相談を通じて更新される前提の**v0.1ドラフト**であり、確定仕様ではない。

---

## 1. 背景・目的

- KP代行という形で『月夜が魅せる物語』を運営してきた経験を活かし、同シナリオを題材にした
  一人プレイ可能なデジタルゲームを制作する。
- TRPGは「毎回KPを立てて遊ぶ」コストが発生するのに対し、本プロジェクトはそのコストなしで
  何度でも・一人でも遊べる形にすることを狙う。
- 既存のAI-KP作品が「TRPGのライブ感の再現」を志向するのに対し、本作は
  **あらかじめ作り込まれたマルチエンディング構造**によって、原作の魅力（コズミックホラー、
  陰謀劇、キャラクタードラマ）を別の角度から再体験できるものを目指す。

## 4. ゲームコンセプト

- **ジャンル**：ビジュアルノベル／アドベンチャー ＋ 育成・シミュレーション要素
- **トーン**：現代日本（2016年12月・東京）を舞台にしたコズミックホラー。都市の日常に紛れ込む
  邪神信仰と陰謀、失踪事件の謎解き
- **コアループ（提案）**：
  1. 日ごとに行動（聞き込み・調査・休息・NPCとの接触）を選択する
  2. 選択・調査の成否によって「調査力」「正気度(SAN)」「NPCとの関係値」が変動する
  3. 各種パラメータとイベントフラグの組み合わせにより、後半の分岐・エンディングが変化する
- **想定プレイ時間**：原作シナリオのボリューム（100ページ超・複数セッション相当）を踏まえ、
  フル実装時は初回プレイで**8〜15時間程度**を想定（TRPGセッション数回分に相当するテキスト量）。
  2周目以降は既読スキップ等により短縮可能。MVP（フェーズ1）はこのうち導入部のみを対象とする

## 5. ストーリー設計

### 5.1 原作の全体プロット（要約）

1. **導入**：2016年12月21日夜、新橋の居酒屋「夜叉」に集まった探索者たちが、私立探偵・瑞名慧から
   「東風谷雪」という少女の捜索を依頼される。
2. **背景**：東風谷雪は2015年に起きた「東京23区連続行方不明事件」（28人が失踪）の被害者の一人で、
   邪教「星の知恵派」に拘束され、シュブ＝ニグラスの眷属「ゴフン・フーパジ・シュブ＝ニグラス」へと
   変貌させられていた。親友の間宮凛久も同様に囚われ、洗脳されている。
3. **調査**：探索者は「満月と新月の教団」「星の知恵派」「銀の黄昏教団」「バベッジ・インコーポレイテッド」
   といった複数組織の陰謀に巻き込まれながら、東風谷雪・間宮凛久の行方と、真の黒幕「遠藤啓介」
   （実は"隠された女神個体"）の企みに迫っていく。
4. **クライマックス**：12月29日21時、哲学堂公園でシュブ＝ニグラス降臨の儀式が行われる。
   探索者の調査・行動の成果次第で、この儀式の結末が大きく変わる。

### 5.2 分岐フラグ（原作の結末条件をゲーム用に整理）

原作「14.結末」に基づき、以下の主要フラグでエンディングが分岐する構造を踏襲する。

| # | フラグ | 内容 |
|---|---|---|
| F1 | ムーンレンズ奪取 | 儀式のキーアイテムを哲学堂公園で奪取できたか |
| F2 | 東風谷雪 救出 | 生還させられたか |
| F3 | 間宮凛久 救出 | 12/28 21:00までに洗脳を解除できたか（タイムリミットあり） |
| F4 | 死へと誘う印 解除 | ナイ牧師の切り札を無効化できたか |
| F5 | 遠藤啓介の野望阻止 | 対話・説得・実力行使等で真の黒幕を止められたか |

- 方針として「原作から想定できるエンディングは大体実装する」ことが確定した。
  理論上の組み合わせ（最大32通り）をすべて個別テキスト化するのは非現実的なため、
  **原作「14.結末」の記述に基づく分岐構造を軸に、以下の7エンディングへ集約**することを提案する。
  各エンディング内でF2・F3（雪／凛久の生死）等の達成度に応じた**差分エピローグ文**を
  重ねる形で「ほぼ全結末を再現」しつつ、執筆量を現実的な範囲に収める。

| Ending | 成立条件（主要フラグ） | 概要 |
|---|---|---|
| ① 真エンド（大団円） | F1成功・F2成功・F3成功・F5成功 | 儀式阻止、雪・凛久ともに生還、遠藤啓介の野望を阻止。教団壊滅、東京に平穏が戻る |
| ② グッドエンド（勝利と代償） | F1成功・F5成功だが F2/F3のどちらかが未達成 | 儀式は止められるが、雪か凛久のどちらかを救えなかった |
| ③ ノーマルエンド（黒幕を止められず） | F1成功・F5失敗 | 儀式は止まるが、遠藤啓介本人は目的を諦めず日本を去る（IDE2.0計画は継続） |
| ④ 限定的破滅エンド | F1失敗・F4成功 | ムーンレンズを奪えず儀式は決行されるが、死へと誘う印を解除済みのため被害が限定される |
| ⑤ 真バッドエンド（東京壊滅） | F1失敗・F4失敗 | シュブ＝ニグラス降臨、関東3000万人が生贄に。ナイ牧師が望む世界が実現する |
| ⑥ 特殊エンド（遠藤啓介ルート） | 遠藤啓介と対話し真相を聞いた上での選択分岐 | 彼を引き留めるか見送るかで、IDE2.0による人類変容の行方が変わる隠しルート |
| ⑦ 早期離脱エンド | 探索序盤での重大な選択ミス・SAN枯渇等 | TRPGでいう「探索者死亡・離脱」に相当する隠しバッドエンド |

- 各エンディングの正式な分岐条件・演出詳細はフェーズ2以降のシナリオ執筆時に詰める。
  本表はその際の設計指針として扱う。

## 6. ゲームシステム要件（提案）

### 6.1 ビジュアルノベル要素
- 地の文＋会話テキスト表示、選択肢分岐、背景・立ち絵・BGM/SEによる演出
- 既読スキップ、バックログ、オートセーブ／複数セーブスロット

### 6.2 演出方針：ホラー表現

- ジャンプスケア（大音量・急な画面変化で驚かせる演出）は**基本的に使用しない方針**とする
- 代わりに「じっとりした恐怖感」「じわじわと追い詰められる焦燥感」を軸に、
  BGM・テキストの間・SANの数値低下といった**静的・積み上げ型の演出**をアクセントとして使う
- コズミックホラーらしい「理解できないものへの恐怖」「日常が侵食されていく感覚」を大切にする

### 6.3 育成・シミュレーション要素（本作の独自性のコア）
- **日付・時間帯システム**：原作の12/21〜12/29という限られた期間を、
  「日×時間帯（例：昼／夕方／夜）」の行動枠として扱う、カレンダー型の進行にする
- **4方向スキルライン（知識・探索・交渉・戦闘）**：7章で定義した主人公の成長システム。
  原作の「技能ロール」「情報取得難度ランク0〜4」の概念を翻案し、数値が高いほど
  有利な選択肢・入手できる情報が増える。目指すエンディングに応じて重点的に
  伸ばすラインが変わるのが本作のコア駆け引き
- **正気度(SAN)**：ホラー演出・戦闘・真実の開示のたびに消費されるリソース。
  低下すると使える選択肢が狭まる／専用の悪い分岐に近づく
- **NPC関係値**：瑞名慧・久美啓太・東風谷雪・間宮凛久など主要NPCとの関係値を管理し、
  終盤の協力可否や個別エピローグに反映する

### 6.4 探索パート
- マップ選択式（原作に登場する居酒屋「夜叉」「中野ヒカリエビル」「哲学堂公園」等の
  地点をリスト／簡易マップから選び、調査コマンドを実行する形式を提案）
- コマンド選択の結果は「調査力」パラメータや既存フラグに応じて分岐する

**性別選択に伴う実装上の留意点（次フェーズで詳細設計）**

- Ren'Pyでは主人公の性別を変数化し、地の文・セリフの一部をテキスト置換／分岐で出し分ける設計とする
- 立ち絵アセット（AI生成）も男女2パターン用意する必要がある

### 7.1 スキル成長システム（原作ハンドアウトを流用）

原作の4種のハンドアウトを「複数キャラの選択」としてではなく、
**主人公1人の初期タイプ＋成長先の4方向**として再設計する。

- **初期タイプ＝ハンドアウト4（クトゥルフ神話技能）寄り**でスタートする。
  オカルト・知識技能を軸にした、真相に一歩近い視点を持つ主人公。
- ゲーム進行中の育成要素（調査行動の選択・成功体験の蓄積）によって、
  残る3方向のスキルラインを**後天的に伸ばせる**。

| スキルライン | 由来 | 主な用途（推奨技能） |
|---|---|---|
| 知識・オカルト（初期値） | ハンドアウト4 | 真相の理解、神話知識、「死へと誘う印」の解除条件を読み解く（F4と関連） |
| 探索 | ハンドアウト1 | 尾行・変装・ナビゲートで隠された場所を突き止める（ムーンレンズ捜索＝F1、雪・凛久の潜伏先特定＝F2/F3と関連） |
| 交渉 | ハンドアウト2 | NPCとの交渉・説得（遠藤啓介との対話＝F5、各組織との駆け引きと関連） |
| 戦闘 | ハンドアウト3 | 実力行使が必要な局面（カルティストとの直接対決、土壇場の身の安全確保と関連） |

- **「狙ったエンドに辿り着くには狙った技能を伸ばす必要がある」を核ルールとする**：
  5.2章の7エンディングは、上表のスキルラインの育成状況（＋フラグF1〜F5の達成）に
  応じて到達可能性が変わる設計とする。プレイヤーは「今回はどの技能を伸ばして、
  どの結末を目指すか」を選びながら周回するゲーム性になる。
- 具体的な数値設計（成長ポイントの獲得方法・必要閾値など）はフェーズ2のシステム詳細設計で詰める。

## 10. プラットフォーム・技術要件（確定：Ren'Py案）

原作をほぼ丸ごと実装する方針（フル実装時8〜15時間相当のテキスト量）となったため、
大量の分岐テキストを効率よく書けることを最優先し、**Ren'Pyを採用する**。

| 項目 | 内容 | 理由 |
|---|---|---|
| エンジン | Ren'Py（Python製ノベルゲームエンジン） | `label`/`jump`/`menu`等の専用記法で大量の分岐テキストを高速に書ける。セーブ／ロード／既読スキップ／バックログ／立ち絵差分などノベルゲームに必要な機能が標準装備で、育成要素（変数管理・ステータス画面）もPythonコードで柔軟に組める |
| 配布形態 | Windows/Mac向けの実行ファイル（exe/app）としてビルド | 身内配布において「インストール不要でダブルクリックで起動」が可能 |
| セーブデータ | Ren'Py標準のセーブ機能を利用 | 複数スロット・オートセーブに標準対応 |
| 開発・検証方法 | 本環境（Claude Code）に Ren'Py 8.1.3 をインストールし動作検証済み。`renpy lint`による構文チェックに加え、**Xvfb（仮想ディスプレイ）+ ソフトウェアレンダラーの組み合わせでゲームループの起動を確認**できたため、スクリーンショット等を用いた視覚確認もこの環境内である程度可能。最終的な演出の細部確認はユーザー側の環境でも行っていただく想定 | — |
| Web版の扱い | Ren'Pyは公式にHTML5/Webエクスポート機能を持つため、将来的にブラウザ共有したくなった場合も同じソースから書き出せる | 当初検討していたWeb React案の「共有しやすさ」のメリットを、Ren'Pyのweb export機能で代替できる見込み |

→ 次のステップとして、本開発環境（Claude Code / このコンテナ）でRen'Pyプロジェクトの
ビルド・構文チェックがどこまで可能かを検証する（GUIプレビューができない制約への対処方法を含む）。

## 12. スコープ定義（MVP／段階リリース案）

原作は100ページを超えるボリュームがあり、最終的には7エンディングをほぼ網羅する方針のため、
一括実装は工数リスクが高い。以下の段階分けとする。

- **フェーズ0（本ドキュメント）**：要件定義
- **フェーズ1（MVP・確定）**：**12/21 居酒屋「夜叉」〜東風谷雪との遭遇イベントまで**を実装対象とする。
  このMVP範囲は**分岐なしの一本道**でよい（選択肢によるゲームオーバーや分岐は本フェーズでは作らない）。
  実装内容：
